## 2. 执行命令与结果

在项目根目录的 Windows PowerShell 中执行：

```powershell
Set-Location backend
..\.venv\Scripts\python.exe -m scripts.database check
..\.venv\Scripts\python.exe -m pytest ..\tests -q -p no:cacheprovider --basetemp ..\tests\pytest-stage8
..\.venv\Scripts\python.exe -m scripts.experiment --repeats 5
```

本次 `database check` 输出：`MySQL connected; database exists: True; expected tables: 13/13`。完整 pytest 回归输出：**35 passed in 3.88s**。上述测试实际连接本机 MySQL；涉及 RAG 的集成测试使用真实 Chroma 持久化及测试专用模型替身。`pytest` 的临时目录在本机受沙箱权限影响，本次完整测试在获准的沙箱外执行。

浏览器联调使用运行中的 `http://127.0.0.1:8004/`：首页从 API 显示考生 1、院校 9、专业 9、知识文档 0；院校查询展示 9 条且来源为“模拟数据”；Agent 页显示已有运行 #42 的六个节点均完成；历史方案页显示方案 #39 的 6 条明细。知识库检索在本机返回“尚未配置 Embedding 服务”的明确提示。浏览器联调使用已有演示记录，未以静态数据冒充接口结果。

## 4. 未覆盖或受限事项

1. 未接入真实 Embedding/LLM 服务，真实政策检索质量、引用准确性及问答正确性尚不能验收。测试替身仅验证调用路径与存储/检索机制。
2. 全部招生与录取记录均为模拟数据；没有经核验的官方数据，也没有真实录取结果标签，因此不能评价录取概率或实际填报成效。
3. 工作流接口为同步执行；Agent 页能查看已写入事件，推荐请求期间不能基于尚未返回的运行 ID 实时展示每个节点。
4. 本次浏览器联调覆盖主要页面和错误状态，未做跨浏览器、并发负载或大规模数据压力测试。性能数据是单机小样本采样，解释范围见实验分析。

## 5. 结论

在当前模拟数据、测试专用模型替身及本机环境下，已列出的 35 项自动化测试均通过，数据库结构检查和主要前后端路径可运行。真实模型接入、正式数据核验与更大规模测试仍是交付前的待办项；上述结果不构成实际志愿填报或录取效果证明。
